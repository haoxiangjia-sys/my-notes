## 0. 前置概念：位和字节 Bit & Byte & Word

> "Bits mean whatever we decide they mean." — 同一串 01111011 可以是数字、字符、像素……取决于**我们怎么解释它**。

| 术语 | 定义 |
|:-----|:-----|
| **Bit 位** | 一个二进制数字，0 或 1 |
| **Byte 字节** | 8 位 |
| **Word 字** | w 位（CPU 自然处理的宽度，如 32-bit CPU 中 word = 32） |

### 大小端 Endianness

| | Little-Endian 小端 | Big-Endian 大端 |
|:--|:-------------------|:-----------------|
| 读法 | **从右往左** | **从左往右** |
| LSB（最低有效位）| 在最右边 | 在最左边 |
| MSB（最高有效位）| 在最左边 | 在最右边 |
| 类比 | `123` 个位在最右（自然）| 从左往右写数 |

```
X = 1111011

Little-endian 读法: X₀(最右)=1, X₁=1, ..., X₆(最左)=1
Big-endian 读法:    X₀(最左)=1, X₁=1, ..., X₆(最右)=1
                    写法一样，但 X₀ 是谁完全不同！
```

### 汉明度量 Hamming

| 术语 | 含义 | 公式 |
|:-----|:-----|:-----|
| **Hamming Weight** 汉明重量 | X 中**1 的个数** | HW(X) = Σ Xᵢ |
| **Hamming Distance** 汉明距离 | X 和 Y 中**不同位的个数** | HD(X,Y) = Σ (Xᵢ ⊕ Yᵢ) |

```
X = [1,0,0,1]   HW(X) = 1+0+0+1 = 2
Y = [0,1,1,1]   HD(X,Y) = (1⊕0)+(0⊕1)+(0⊕1)+(1⊕1) = 1+1+1+0 = 3
```

> 汉明距离应用：错误检测与纠错码（Hamming code）、数据去重、相似度度量。

## 1. 冯·诺依曼架构 vs 哈佛架构 Von Neumann vs Harvard

### 冯·诺依曼架构 Von Neumann Architecture
```
                    ┌──────────────┐
                    │     CPU      │
                    │  ┌────────┐  │
    输入 Input ────► │  │ 控制单元 │  │
                    │  │ Control │  │
    输出 Output ◄── │  │  ALU   │  │
                    │  └────────┘  │
                    └──────┬───────┘
                           │
                    ┌──────┴───────┐
                    │   存储器      │
                    │ Memory       │
                    │(指令+数据     │
                    │ Instructions │
                    │  + Data)     │
                    └──────────────┘
```

**特点 Feature**：指令和数据存在**同一个存储器**，共用一条总线 / Instructions and data share the **same memory** and bus

**瓶颈 Bottleneck**：冯·诺依曼瓶颈——取指令和取数据不能同时进行 / Von Neumann bottleneck — can't fetch instruction and data simultaneously

### 哈佛架构 Harvard Architecture
```
    指令存储器 Instruction Memory ◄──► CPU ◄──► 数据存储器 Data Memory
    （只读 Read-only）                           （读写 Read/Write）
```

**特点 Feature**：指令和数据**分开存储**，有独立的地址/数据总线 / Instructions and data are **separated** with dedicated buses

**优点 Advantage**：可以同时取指令和取数据 / Can fetch instruction and data simultaneously

| 架构 Architecture | 存储器 Memory | 总线 Bus | 代表 Example |
|:-----------------|:--------------|:---------|:-------------|
| 冯·诺依曼 Von Neumann | 统一 Unified | 1条 One | 大部分通用CPU General-purpose |
| 哈佛 Harvard | 分离 Separate | 2条 Two | DSP、微控制器 Microcontrollers |

## 2. RISC vs CISC

| 对比 Comparison | RISC | CISC |
|:---------------|:-----|:------|
| **全称 Full name** | Reduced Instruction Set Computer | Complex Instruction Set Computer |
| **指令数量 Instruction count** | 少而精简 Few, simple | 多而复杂 Many, complex |
| **指令长度 Length** | 固定 Fixed | 可变 Variable |
| **执行周期 Cycles** | 单周期（大多数）Single-cycle | 多周期 Multi-cycle |
| **寻址方式 Addressing modes** | 少 Few | 多 Many |
| **代表 Examples** | **ARM**、RISC-V、MIPS | **x86**（Intel/AMD）|
| **设计哲学 Philosophy** | 硬件精简，编译器复杂 / Simple hardware, complex compiler | 硬件复杂，编译器简单 / Complex hardware, simple compiler |

### 为什么 RISC 现在更流行？Why is RISC dominant today？
- 功耗更低 Lower power consumption（手机、平板都需要ARM / Mobile devices use ARM）
- 更容易实现流水线 Easier to pipeline
- 苹果 M 系列芯片（ARM架构）性能已经追上 x86 Apple M-series chips
- RISC-V 开源免费 Open-source and free

## 3. 三种处理器范式 Three Processor Paradigms

> 三种组织计算的方式：**操作数从哪儿来、结果放哪儿去？**

### 类比：三种厨房

| | 栈机 | 累加器机 | 寄存器机 |
|:--|:-----|:--------|:--------|
| 类比 | **叠盘子** | **单灶台** | **多灶台** |
| 操作数位置 | 栈顶（隐含） | 累加器（隐含） | 寄存器（显式编号） |
| 3+4 指令数 | 3 条 | 2 条 | 3 条 |
| 访存次数 | 多（栈在内存） | 中 | 少（寄存器快） |
| 代表 | JVM、WebAssembly | 早期单片机 | **ARM、x86、RISC-V** |

### ① 栈机 Stack Machine：像叠盘子

```
操作数都在"栈"上，指令只说"做什么"，东西默认在栈顶。

  PUSH 3    // 栈: [3]
  PUSH 4    // 栈: [3,4]
  ADD       // 弹出 3,4 → 压入 7 → 栈: [7]

特点：指令极短（ADD 不需要 operand），但频繁访存 → 慢
```

### ② 累加器机 Accumulator Machine：像单灶台

```
只有一个"累加器" ACC，一切运算围绕它。

  LOAD 3    // ACC = 3
  ADD  4    // ACC = ACC + 4 = 7

特点：极简硬件，但瓶颈明显——所有数据必须过 ACC
```

### ③ 寄存器机 Register Machine：像多灶台

```
多个通用寄存器，编译器可以灵活分配。

  ADDI R1, R0, 3    // R1 = 3  (R0 恒为 0)
  ADDI R2, R0, 4    // R2 = 4
  ADD  R3, R1, R2   // R3 = 7

特点：寄存器是 CPU 中最快的存储（比内存快 ~100 倍），充分利用这一点
```

> **现代 CPU 全部是寄存器机** —— 编译器能把变量合理分配到寄存器，减少访存，性能最优。

## 4. 进制与整数表示 Number Systems & Integers

> 📖 详见 [[计算机笔记/00-定义汇总]]

### 位权展开 Positional Number System

任何进制 b 的数都可以按权展开：

```
x^ = x̂₀, x̂₁, ..., x̂ₙ₋₁    →   x = Σ x̂ᵢ × bⁱ

例：123₁₀  = 3×10⁰ + 2×10¹ + 1×10²  = 3 + 20 + 100 = 123
    1111011₂ = Σ x̂ᵢ × 2ⁱ  = 123₁₀
    173₈     = 3×8⁰ + 7×8¹ + 1×8²  = 123₁₀
    7B₁₆     = 11×16⁰ + 7×16¹ = 123₁₀
```

### 无符号整数 Unsigned

| 定义 | 自然二进制展开 |
|:-----|:---------------|
| 范围 | 0 ≤ x ≤ 2ⁿ − 1 |
| 例（n=8）| 00000000 = 0, 11111111 = 255 |

### 有符号整数 Signed：两种方案

| | Sign-Magnitude 原码 | Two's Complement 补码 |
|:--|:--------------------|:----------------------|
| 方法 | MSB 是符号（0=正，1=负），其余是数值 | MSB 权重为 **−2ⁿ⁻¹**，其余正常 |
| 零的表示 | 两个零：+0 (00...0) 和 −0 (10...0) | **唯一零**：00...0 |
| 范围（n=8）| −127 … 127 | **−128 … 127** |
| 加法 | 需要特殊处理符号 | **直接加就行！不需要额外电路** |
| 使用 | 几乎不用 | **所有现代计算机都用补码** |

```
补码例子（n=8）：
  01111011 = 0×(−128) + 64+32+16+8+0+2+1 = +123
  10000101 = 1×(−128) + 0+0+0+0+4+0+1  = −123
  11111111 = 1×(−128) + 64+32+16+8+4+2+1 = −1
```

### 移位 = 乘除法 Shift = Multiply/Divide

> 左移 y 位 = 乘以 2ʸ，右移 y 位 = 除以 2ʸ

```
C 语言：
  0x8AC << 2  →  2220 × 4 = 8880
  0x8AC >> 2  →  2220 / 4 = 555
```

> 💡 移位比乘法指令快得多，编译器优化时常用移位替代 ×2 的乘法。
