## 1. 中断与异常 Interrupts and Exceptions

### 基础概念

| 术语 | 说明 | 例子 |
|:-----|:------|:------|
| **中断 Interrupt** | **硬件**触发的异步事件 | 键盘按键、网卡数据到达 |
| **异常 Exception** | **CPU 内部**的同步事件 | 除零、缺页、非法指令 |
| **陷阱 Trap** | **软件主动触发**（故意的）| 系统调用 `syscall` |

```
中断：外部设备 → CPU（异步，任何时候都可能来）
异常：指令执行时出错 → CPU（同步，和当前指令相关）
陷阱：程序主动叫 CPU（同步，故意的）

        异步                   同步
   ┌──────────┐          ┌──────────┐
   │  中断    │          │  异常    │
   │  Interrupt│         │ Exception│
   │ (外部)   │          │ (内部)   │
   └──────────┘          └──────────┘
```

### 中断处理流程

```
正常程序 Normal execution
    │
    ├──← 中断信号 IRQ（Interrupt ReQuest）
    │
    ▼
1. 保存现场 Save context
   - PC（返回地址）
   - 状态寄存器 Status Register（标志位）
   
2. 识别中断源 Identify source
   - 查中断向量表 IVT（Interrupt Vector Table）
   - 中断向量表存的是"每个中断号对应的处理程序地址"

3. 跳转到中断处理程序 Jump to ISR
   - 关中断（可选，防止嵌套中断）
   
4. 处理中断 Handle interrupt
   - 读键盘数据 / 接收网络包...
   - 发 EO1（End of Interrupt）信号

5. 恢复现场 Restore context
   - 恢复 PC 和状态寄存器
   - 开中断

6. 返回原程序 Return (IRET / RTI)
    │
    ▼
正常程序 继续执行
```

### 中断向量表 Interrupt Vector Table

```
内存中的一张表：
┌──────────┬────────────────────┐
│ 中断号   │ ISR 地址           │
├──────────┼────────────────────┤
│ 0        │ 除零异常处理程序   │
│ 1        │ 键盘中断处理程序   │
│ 2        │ 定时器中断处理程序 │
│ ...      │ ...                │
│ N        │ 系统调用入口       │
└──────────┴────────────────────┘

CPU 收到中断信号 → 查 IVT → 跳转到对应 ISR
```

### 中断优先级

多个中断同时发生时，CPU 先处理优先级高的：

```
高优先级  ██ 内部异常（除零、页错误...）
         ██ 不可屏蔽中断 NMI
         ██ 硬件中断（磁盘、网卡...）
低优先级  ██ 软件中断（系统调用...）
```

### 中断 vs 轮询（复习）

| 方式 | 优点 | 缺点 |
|:-----|:-----|:------|
| **轮询 Polling** | 简单、可预测 | 浪费 CPU 周期（空转检查）|
| **中断 Interrupt** | CPU 高效（有事才处理）| 复杂、有额外开销（保存/恢复现场）|

**什么时候用轮询？**
- 设备非常快（中断开销 > 轮询开销）
- 实时系统（需要确定性的响应时间）

## 2. 调试器 Debuggers

### 调试器如何工作？

调试器（如 GDB）利用**中断机制**来暂停和检查程序：

```
调试器的核心机制：断点 = 软件中断

当你在某行设断点：
  1. 调试器把该位置的指令替换为 0xCC（x86 的 INT 3）
  2. CPU 执行到 0xCC → 触发断点异常
  3. 调试器捕获异常 → 暂停程序 → 让你检查寄存器/内存/变量
  4. 你按"继续" → 调试器恢复原指令 → 程序继续
```

### 调试器功能

| 功能 | 实现机制 |
|:-----|:---------|
| **断点 Breakpoint** | 替换指令为软件中断 |
| **单步 Step** | CPU 的单步模式（EFLAGS 的 TF 位）|
| **查看寄存器** | 读取 CPU 寄存器（通过 OS 接口）|
| **查看内存** | 读取进程地址空间 |
| **调用栈** | 读栈上的帧指针链 |
| **条件断点** | 每次断点触发时检查条件，不满足就继续 |

### Apollo 制导计算机案例

**Apollo Guidance Computer (AGC)** 是 1960 年代登月用的计算机：

```
AGC 的特点：
  - 字长：15 位 + 1 位奇偶校验
  - 内存：2048 字 RAM + 36K 字 ROM（磁芯 + 编织 ROM）
  - 速度：约 40K 次加法/秒
  - 中断：有 7 个优先级的中断

AGC 的中断系统：
  - 每 10ms 有一次定时器中断（用于实时导航计算）
  - 键盘/显示中断（宇航员输入）
  - 各种传感器中断
```

**AGC 的调试器**：
- 有类似断点的机制
- 可以在飞行中修改内存（通过上传补丁）
- 著名的"1201/1202 报警"：任务优先级设计让计算机在过载时重启低优先级任务

> 课程意义：**中断系统在早期计算机中就存在，且是实时系统（如登月）的关键**

## 3. 系统调用 System Calls

### 什么是系统调用？

程序请求 OS 服务的方式（如读写文件、创建进程）：

```
用户程序（User mode）
    │
    ├─── 调用 printf("Hello") ───┐
    │                            │
    │                  libc 库函数
    │                            │
    │             调用系统调用（如 write()）
    │                            │
    │    ┌───────────────────────┘
    ▼    ▼
  系统调用接口 → 触发陷阱（trap/syscall 指令）
    │
    ▼
操作系统内核（Kernel mode）
    │  处理请求（如写数据到显示器）
    ▼
返回到用户程序
```

### 用户态 vs 内核态

| 模式 | 权限 | 能做什么 |
|:-----|:-----|:---------|
| **用户态 User Mode** | 受限 | 只能执行非特权指令 |
| **内核态 Kernel Mode** | 完全 | 可执行所有指令（包括 I/O、修改页表...）|

**从用户态到内核态的三种方式**：
1. 系统调用（trap 指令，主动）
2. 异常（除零、缺页，被动）
3. 中断（外部设备，异步）

### ⚠️ Common Mistakes / 易错点
- **Interrupt = asynchronous** (from hardware, can happen anytime) / 异步
- **Exception = synchronous** (from instruction execution, e.g., divide by zero) / 同步
- **Trap = intentional** (software requests OS service via syscall) / 主动触发
- **Don't confuse**: TLB Miss ≠ Interrupt (TLB miss is handled by hardware, not an interrupt) / 不要搞混
- **Debubgger breakpoint**: replaces instruction with 0xCC (INT 3), NOT a hardware interrupt / 断点替换指令为 0xCC
