## 1. 总线与互连 Buses and Interconnects

### 什么是总线？

**总线 Bus** = CPU、内存、I/O 设备之间传输数据的**共享通信通道**

### 总线结构

```
          ┌──────┐   ┌──────┐   ┌──────┐   ┌──────┐
          │ CPU  │   │ 内存  │   │ I/O  │   │ I/O  │
          │      │   │      │   │  1   │   │  2   │
          └──┬───┘   └──┬───┘   └──┬───┘   └──┬───┘
             │          │          │          │
    ┌────────┴──────────┴──────────┴──────────┴─────┐
    │                 系统总线 System Bus            │
    │  ┌────────────────────────────────────────┐   │
    │  │  数据总线 Data Bus（8/16/32/64 位）    │   │
    │  ├────────────────────────────────────────┤   │
    │  │  地址总线 Address Bus                  │   │
    │  ├────────────────────────────────────────┤   │
    │  │  控制总线 Control Bus                  │   │
    │  └────────────────────────────────────────┘   │
    └──────────────────────────────────────────────┘
```

### 三种总线

| 总线 | 方向 | 宽度（Hex 8）| 作用 |
|:-----|:-----|:------------|:-----|
| **数据总线 Data Bus** | 双向 | 8 位 | 传输数据/指令 |
| **地址总线 Address Bus** | 单向（CPU→其他） | 8 位 | 指定内存/I/O 地址 |
| **控制总线 Control Bus** | 双向 | 若干 | 控制信号（读/写/中断...）|

### 总线仲裁 Bus Arbitration

多个设备都想用总线 → 需要**仲裁器**决定谁先用：
- **菊花链 Daisy chain**：设备按优先级串联
- **集中式 Centralized**：专门的仲裁器

### 冯·诺依曼瓶颈（总线视角）

> CPU 和内存共用总线 → **总线**是瓶颈，不是 CPU 速度

```
CPU 要读指令 → 用总线
CPU 要读数据 → 用总线
两者不能同时发生！→ 冯·诺依曼瓶颈
```

## 2. Hex 8 存储器系统

### Hex 8 内存映射

```
Hex 8 有 256 字节内存（8 位地址），通常划分：
┌──────────────────────┐ 0xFF  (255)
│   I/O 端口映射       │
│   Memory-mapped I/O  │
├──────────────────────┤
│                      │
│   程序/数据区         │
│   Program & Data     │
│                      │
├──────────────────────┤ 0x10  (16)
│   Hex 8 Monitor      │
│   （监控程序）       │
├──────────────────────┤ 0x00  (0)
```

### Hex 8 的 I/O

- **内存映射 I/O**：一部分内存地址映射到 I/O 设备
- **INP/OUT 指令**：专门用于 I/O 操作（Hex 8 有 `INP port` 和 `OUT port`）

```
INP port  →  R0 = I[port]   （从端口读数据到 R0）
OUT port  →  O[port] = R0   （把 R0 数据写到端口）
```

## 3. 流水线 Pipelining

### 什么是流水线？

把指令执行分成多个**阶段**，每个阶段由独立的硬件处理，**重叠执行**多条指令。

### 非流水线 vs 流水线

```
非流水线（每条指令完成后再取下一条）：
┌─────┬─────┬─────┐
│ I1  │ I2  │ I3  │  ← 顺序执行
└─────┴─────┴─────┘
时间 →

5 级流水线（理想情况）：
         Cycle:  1   2   3   4   5   6   7   8
I1:              F   D   E   M   W
I2:                  F   D   E   M   W
I3:                      F   D   E   M   W
I4:                          F   D   E   M   W
I5:                              F   D   E   M   W

F = Fetch（取指）  D = Decode（译码）  E = Execute（执行）
M = Memory（访存） W = Writeback（写回）

吞吐量：每周期完成 1 条指令（理想情况）
```

### 流水线阶段（5 级 RISC 经典）

| 阶段 | 做的事 | 硬件 |
|:-----|:-------|:-----|
| **IF (Fetch)** | 从指令存储器取指令 | PC + 指令存储器 |
| **ID (Decode)** | 译码、读寄存器 | 控制单元 + 寄存器文件 |
| **EX (Execute)** | ALU 运算 / 地址计算 | ALU |
| **MEM (Memory)** | 读/写数据存储器 | 数据存储器 |
| **WB (Writeback)** | 结果写回寄存器 | 寄存器文件 |

### 流水线性能

```
理想加速比 = 流水线级数
实际加速比 < 级数（因为 Hazards）

例：不流水线：1 条指令 5 个周期
    5 级流水线：1 条指令仍要 5 个周期，但每周期完成 1 条
    吞吐量提升 5 倍（无 Hazards 时）
```

## 4. 冒险 Hazards

### 三种 Hazards

| 类型 | 原因 | 类比 |
|:-----|:-----|:------|
| **结构冒险 Structural** | 硬件资源冲突 | 两个人想同时用同一台打印机 |
| **数据冒险 Data** | 下条指令依赖上条结果 | 你等我算完才能用我的结果 |
| **控制冒险 Control** | 分支/跳转改变控制流 | 岔路口不知道往哪走 |

### 结构冒险 Structural Hazard

```
HW 只有一个存储器（冯·诺依曼架构）：
I1:  F   D   E   M   W
I2:      F   D   E   M   W
I3:          F   D   E   M  W
                  ↑
            冲突！I3 取指和 I1 访存同时用存储器

解决：哈佛架构（指令/数据分离）或 插入气泡（stall）
```

### 数据冒险 Data Hazard

```
ADD R1, R2, R3    ; R1 = R2 + R3
SUB R4, R1, R5    ; R4 = R1 - R5 ← 需要 R1！

          Cycle: 1   2   3   4   5
ADD:            F   D   E   M   W
SUB:                F   D   E   M   W
                            ↑
                   SUB 在 D 阶段读 R1，但 ADD 在 W 阶段才写完 R1！
```

**解决办法**：

| 方法 | 说明 | 代价 |
|:-----|:-----|:-----|
| **插入气泡 Stall** | 插入 NOP 等待 | 降低性能 |
| **转发 Forwarding/Bypassing** | ALU 结果直接传给下条指令（不经过寄存器）| 需要额外硬件 |
| **编译器调度** | 编译器重新排列指令 | 编译期优化 |

```
转发示例：
          Cycle: 1   2   3   4   5
ADD:            F   D   E   M   W
SUB:                F   D──E──M   W
                            ↑
                   转发：E 阶段的 ALU 结果直接给 SUB 的 EX 阶段
```

### 控制冒险 Control Hazard

```
BEQ R1, R2, target  ; 如果 R1=R2 跳到 target
ADD R3, R4, R5       ; 下一条？不一定执行！

         Cycle: 1   2   3   4
BEQ:          F   D   E   M   
???           F   ── ??? ──    
                  ↑
         BEQ 在 E 阶段才知道是否跳转
         但 IF 已经取了下一指令！

解决：
1. 分支预测 Branch Prediction：猜是否跳转
   - 静态：总是猜不跳 / 总是猜跳
   - 动态：用历史记录预测（2 位饱和计数器）
2. 延迟槽 Delay Slot：分支后的指令总是执行
3. 刷新 Flush：猜错了就清空流水线
```

## 5. 存储层次 Memory Hierarchy（W17 复习 + 补充）

> 详细笔记见 [[计算机笔记/05-存储系统\|05-存储系统]]，这里只补充 TB2 重点

### TB2 补充：局部性对流水线的影响

```
空间局部性好 → Cache 命中率高 → 流水线很少等内存
时间局部性好 → 循环效率高 → 分支预测更容易

局部性差 → Cache 频繁 Miss → 流水线经常停顿 → 性能大幅下降
```

### TB2 补充：Cache 与总线

```
Cache Miss 时：
  CPU 必须通过总线从内存读数据
  总线带宽 → 决定 miss penalty 的关键因素
  多核 CPU 中多个核共享总线 → 竞争更激烈
```

### 📝 经典考题：流水线 + Hazard

**题型：给指令序列，画流水线图，标 Hazard**

```
题目：
指令序列（MIPS风格）：
  LW R1, 0(R2)    ; R1 = M[R2]
  ADD R3, R1, R4  ; R3 = R1 + R4
  SW R3, 0(R5)    ; M[R5] = R3
  ADD R6, R7, R8  ; R6 = R7 + R8

5 级流水线：IF ID EX MEM WB
试分析数据冒险，并画出 forwarding 后的流水线图

解题步骤：
Step 1: 识别数据依赖
  ADD R3,R1,R4 依赖 LW 的 R1 → RAW 冒险
  SW R3,0(R5) 依赖 ADD 的 R3 → RAW 冒险

Step 2: 画流水线图（标注 forwarding）
        Cycle: 1   2   3   4   5   6   7
  LW:         IF  ID  EX  MEM WB
  ADD:            IF  ID  EX  MEM WB
                         ↑ forwarding: LW 的 MEM → ADD 的 EX
  SW:                IF  ID  EX  MEM WB
                              ↑ forwarding: ADD 的 EX → SW 的 MEM（如果 SW 需要）
  4th:                   IF  ID  EX  MEM WB
```

### 📝 自测：分支预测

```
题目：循环 10 次的 for 循环，用"静态猜跳转"的分支预测
  猜对几次？猜错几次？
  
答案：猜跳转 → 
  前 9 次循环：跳转 → 猜对 ✓
  最后 1 次：不跳 → 猜错 ✗
  猜对 9 次，猜错 1 次

  猜不跳转 →
  第 1 次：跳转 → 猜错 ✗
  第 2-10 次：都是跳转 → 继续猜错 ✗
  猜对 0 次，猜错 10 次 😱
```

### ⚠️ 易错点
- **数据冒险不一定要 stall**：forwarding 可以解决大部分 RAW 冒险
- **Load-use 情况**：LW 后紧跟 ADD 使用结果 → forwarding 也解决不了（因为 LW 的 MEM 阶段才有数据），需要插 1 个 stall
- **控制冒险的代价** = 分支预测错时 flush 的指令数 × 流水线级数
