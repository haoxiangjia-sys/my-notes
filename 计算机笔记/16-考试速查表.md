## 1. 🔢 Hex 8 指令集（必须背熟）

| Opcode | 指令 | 操作 | 用法 |
|:------:|:-----|:-----|:------|
| 0000 | HLT | 停机 | `HLT` |
| 0001 | LDA addr | R0 = M[addr] | `LDA count` |
| 0010 | STA addr | M[addr] = R0 | `STA count` |
| 0011 | ADD addr | R0 += M[addr] | `ADD count` |
| 0100 | SUB addr | R0 -= M[addr] | `SUB count` |
| 0101 | JMP addr | PC = addr | `JMP loop` |
| 0110 | JGE addr | if R0 ≥ 0: PC=addr | `JGE done` |
| 0111 | JNZ addr | if R0≠0: PC=addr | `JNZ loop` |
| 1000 | INP port | R0 = I[port] | `INP 0` |
| 1001 | OUT port | O[port] = R0 | `OUT 0` |
| 1010 | LDI imm | R0 = imm | `LDI #5` |
| 1011 | ADI imm | R0 += imm | `ADI #-1` |
| 1100 | INC | R0++ | `INC` |
| 1101 | DEC | R0-- | `DEC` |
| 1110 | SHL | R0 <<= 1 | `SHL` |
| 1111 | SHR | R0 >>= 1 | `SHR` |

> ⚡ **operand 只有 4 位** → 直接寻址只能访问 0-15

## 3. ⚡ 流水线与 Hazards（必考画图）

### 5 级流水线
```
F(取指) → D(译码) → E(执行) → M(访存) → W(写回)
```

### 三种 Hazard

| Hazard | 原因 | 解法 |
|:-------|:-----|:-----|
| **结构** | 硬件资源冲突 | 哈佛架构 / 插入 stall |
| **数据** | 下条用上条结果 | **Forwarding**（大部分情况）/ Stall（Load-use）|
| **控制** | 分支/跳转 | 分支预测 / 延迟槽 / Flush |

### Load-use 数据冒险（转发也救不了）
```
LW R1, 0(R2)   ; MEM 阶段才有 R1
ADD R3, R1, R4 ; 下一周期 EX 就需要 → 必须 stall 1 个周期！
```

### 分支预测
```
循环 10 次，"猜跳转"：猜对 9 次，猜错 1 次（最后一次不跳）
猜错代价：flush 流水线已取的指令
```

## 4. 💾 Cache 计算（必考）

### 地址分解
```
地址 = [Tag][Index][Offset]
Offset = log₂(行大小)
Index = log₂(Cache大小 / 行大小 / 相联度)
        （直接映射：行数；N路组相联：组数）
Tag = 地址位宽 - Index位数 - Offset位数
```

### 示例：64KB 直接映射 Cache，64B 行，32 位地址
```
Offset = 6 位（64=2⁶）
行数 = 64KB/64B = 1024 → Index = 10 位
Tag = 32 - 10 - 6 = 16 位
```

### 三种映射
| 方式 | 一个块能放的位置 | 查找 |
|:-----|:---------------|:-----|
| 直接映射 | 1 个（Index 唯一）| 最快 |
| N 路组相联 | N 个 | 较快 |
| 全相联 | 全部 | 最慢 |

### 写策略
| 策略 | 同时写内存？| 脏位？| 速度 |
|:-----|:----------|:------|:-----|
| Write-through | ✅ 同时写 | 无 | 慢 |
| Write-back | ❌ 换出才写 | ✅ 需要 | 快 |

### 性能公式
```
平均访问时间 = Hit Time + Miss Rate × Miss Penalty
```

### 3C Miss
- **Compulsory**：第一次访问
- **Capacity**：Cache 不够大
- **Conflict**：多个地址争同一位置

## 5. 📄 虚拟内存（必考地址转换）

### 虚拟地址 → 物理地址
```
虚拟地址 = [VPN][Offset]
查页表：VPN → PFN
物理地址 = PFN × 页大小 + Offset

示例：
  4KB 页，偏移量 = 12 位
  VPN = VA >> 12
  Offset = VA & 0xFFF
  物理地址 = PFN × 4096 + Offset
```

### TLB 流程
```
VA → TLB查 → Hit? → 物理地址 → Cache → 数据
              ↓ Miss
           查页表 → 更新TLB
              ↓ Valid=0
           Page Fault → 磁盘加载 → 更新页表 → 重新执行
```

### 用户态 vs 内核态
| 模式 | 权限 | 切换方式 |
|:-----|:-----|:---------|
| 用户态 | 受限 | 不能主动进内核 |
| 内核态 | 全部 | 中断/异常/系统调用(trap) |

## 6. 🎨 图着色寄存器分配（必考）

```
步骤：
1. 生命周期分析 → 2. 画干涉图 → 3. 着色 → 4. 分配寄存器

干涉图规则：
  - 节点 = 变量
  - 边 = 两个变量生命周期重叠
  
着色规则：
  - 相邻节点不同色
  - 颜色数 = 可用寄存器数
  - 着色失败 → Spill（放内存）
```

### 边界重叠判定
```
变量 A 最后使用在 line N
变量 B 定义在 line N
→ 不重叠，可共用寄存器！
```

## 11. 📊 Iron Law 性能计算（Past Paper Q5）

```
Time = Instructions × CPI × ClockCycleTime
                ↑           ↑
         指令总数      每指令平均周期数

CPI = Σ(Cycles_i × Count_i) / Σ(Count_i)

示例：
  指令类型    Cycles    次数
  Load        4         20M
  Store       4         15M
  Branch      8         5M
  Arithmetic  1         60M

  Total Instr = 20+15+5+60 = 100M
  CPI = (4×20 + 4×15 + 8×5 + 1×60) / 100
      = (80+60+40+60) / 100 = 240/100 = 2.4

  Time = 100M × 2.4 × (1/2GHz)
       = 100M × 2.4 × 0.5ns
       = 120ms
```

## 12. 🔷 PFIX 前缀指令（Question Bank 考点）

> PFIX 是 Transputer 处理器的概念，Hex 8 类似机制

```
问题：Hex 8 只有 4 位 operand → 只能访问 0-15
PFIX 解法：用一条额外指令扩展 operand

  PFIX #0xF   ; 高 4 位 = 15
  ADD #0xC    ; 低 4 位 = 12
              ; 实际 operand = 0xFC (252)
```

## 13. 🧱 Tombstone Diagram（Past Paper Q4）

```
编译器引导（Bootstrapping）的 T 图：

  ┌──────────┐   ┌──────────┐
  │  Rust    │   │  Rust    │
  │ program  │   │ compiler │
  │          │   │ (binary) │
  │ ARMv7-A  │   │  ARMv7-A │
  └──────────┘   └──────────┘

解释：
  - 第一个 Rust 编译器用 Rust 写，编译成 ARM 二进制
  - 然后用这个二进制编译 Rust 程序
  - 鸡生蛋问题：先用 C 编译器（GCC）编译 Rust 编译器
```

## 14. 💡 True/False 答题策略（Past Paper Q1 占 30 分）

```
Step 1: 明确写 True 或 False（不写不给分）
Step 2: 用 1-2 句话解释原因
   - False: 给出反例（counter-example）或解释错在哪
   - True: 说明为什么在所有情况下都成立
Step 3: 可以用真值表、公式、举例来支撑

答 True 的策略：证明对所有情况都成立（用代数/公式）
答 False 的策略：找一个反例就够了

阅卷规则：
  - 分类正确 + 合理解释 = 满分
  - 只写 True/False 不解释 = 0 分
  - 写多了但正确 = 不扣分
  - 写多了但自相矛盾 = 扣分
```
