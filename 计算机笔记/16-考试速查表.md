## 1. 🔢 Hex 8 指令集（必须背熟）

| Opcode | 指令 | 操作 | 用法 |
|:------:|:-----|:-----|:------|
| 0000 | HLT | 停机 | `HLT` |
| 0001 | LDA addr | R0 = M[addr] | `LDA count` |
| 0010 | STA addr | M[addr] = R0 | `STA count` |
| 0011 | ADD addr | R0 += M[addr] | `ADD count` |
| 0100 | SUB addr | R0 -= M[addr] | `SUB count` |
| 0101 | JMP addr | PC = addr | `JMP loop` |
| 0110 | JGE addr | if R0 ≥ 0: PC=addr | `JGE done` |
| 0111 | JNZ addr | if R0≠0: PC=addr | `JNZ loop` |

| 1001 | OUT port | O[port] = R0 | `OUT 0` |
| 1010 | LDI imm | R0 = imm | `LDI #5` |
| 1011 | ADI imm | R0 += imm | `ADI #-1` |
| 1100 | INC | R0++ | `INC` |
| 1101 | DEC | R0-- | `DEC` |
| 1110 | SHL | R0 <<= 1 | `SHL` |
| 1111 | SHR | R0 >>= 1 | `SHR` |

> ⚡ **operand 只有 4 位** → 直接寻址只能访问 0-15

## 3. ⚡ 流水线与 Hazards（必考画图）

### 5 级流水线
```
F(取指) → D(译码) → E(执行) → M(访存) → W(写回)
```

### 三种 Hazard

| Hazard | 原因 | 解法 |
|:-------|:-----|:-----|
| **结构** | 硬件资源冲突 | 哈佛架构 / 插入 stall |
| **数据** | 下条用上条结果 | **Forwarding**（大部分情况）/ Stall（Load-use）|
| **控制** | 分支/跳转 | 分支预测 / 延迟槽 / Flush |

### Load-use 数据冒险（转发也救不了）
```
LW R1, 0(R2)   ; MEM 阶段才有 R1
ADD R3, R1, R4 ; 下一周期 EX 就需要 → 必须 stall 1 个周期！
```

### 分支预测
```
循环 10 次，"猜跳转"：猜对 9 次，猜错 1 次（最后一次不跳）
猜错代价：flush 流水线已取的指令
```

## 4. 💾 Cache 计算（必考）

### 地址分解
```
地址 = [Tag][Index][Offset]
Offset = log₂(行大小)
Index = log₂(Cache大小 / 行大小 / 相联度)
        （直接映射：行数；N路组相联：组数）
Tag = 地址位宽 - Index位数 - Offset位数
```

### 示例：64KB 直接映射 Cache，64B 行，32 位地址
```
Offset = 6 位（64=2⁶）
行数 = 64KB/64B = 1024 → Index = 10 位
Tag = 32 - 10 - 6 = 16 位
```

### 三种映射
| 方式 | 一个块能放的位置 | 查找 |
|:-----|:---------------|:-----|
| 直接映射 | 1 个（Index 唯一）| 最快 |
| N 路组相联 | N 个 | 较快 |
| 全相联 | 全部 | 最慢 |

### 写策略
| 策略 | 同时写内存？| 脏位？| 速度 |
|:-----|:----------|:------|:-----|
| Write-through | ✅ 同时写 | 无 | 慢 |
| Write-back | ❌ 换出才写 | ✅ 需要 | 快 |

### 性能公式
```
平均访问时间 = Hit Time + Miss Rate × Miss Penalty
```

### 3C Miss
- **Compulsory**：第一次访问
- **Capacity**：Cache 不够大
- **Conflict**：多个地址争同一位置

## 5. 📄 虚拟内存（必考地址转换）

### 虚拟地址 → 物理地址
```
虚拟地址 = [VPN][Offset]
查页表：VPN → PFN
物理地址 = PFN × 页大小 + Offset

示例：
  4KB 页，偏移量 = 12 位
  VPN = VA >> 12
  Offset = VA & 0xFFF
  物理地址 = PFN × 4096 + Offset
```

### TLB 流程
```
VA → TLB查 → Hit? → 物理地址 → Cache → 数据
              ↓ Miss
           查页表 → 更新TLB
              ↓ Valid=0
           Page Fault → 磁盘加载 → 更新页表 → 重新执行
```

### 用户态 vs 内核态
| 模式 | 权限 | 切换方式 |
|:-----|:-----|:---------|
| 用户态 | 受限 | 不能主动进内核 |
| 内核态 | 全部 | 中断/异常/系统调用(trap) |

## 6. 🎨 图着色寄存器分配（必考）

```
步骤：
1. 生命周期分析 → 2. 画干涉图 → 3. 着色 → 4. 分配寄存器

干涉图规则：
  - 节点 = 变量
  - 边 = 两个变量生命周期重叠
  
着色规则：
  - 相邻节点不同色
  - 颜色数 = 可用寄存器数
  - 着色失败 → Spill（放内存）
```

### 边界重叠判定
```
变量 A 最后使用在 line N
变量 B 定义在 line N
→ 不重叠，可共用寄存器！
```

## 10. 📝 简答题实战 Short-Answer Q&A Bank

> 根据你反馈："考试一般都是简答题" — 每题写 2-4 个得分点即可

### Q1: 页表如何实现地址转换？How does a page table translate addresses?

```
Q: "Explain how a page table enables virtual-to-physical address translation."
   "解释页表如何实现虚拟地址到物理地址的转换。"

得分点 Marking points:
  ① 虚拟地址分成 VPN + Offset（如 4KB 页 → Offset 12 位）
  ② 页表是每个进程一张的映射表，VPN 索引查表
  ③ 页表项包含 PFN + Valid bit
  ④ Valid=1 → 物理地址 = PFN × 页大小 + Offset
  ⑤ Valid=0 → Page Fault → OS 从磁盘加载到内存 → 更新页表 → 重新执行

考官追问变体：
  "What happens if the page is not in memory?" → 答第⑤点
  "How does TLB improve this?" → 答 TLB 缓存最近翻译结果，Hit 免查页表
  "Who manages the page table?" → OS (kernel mode)
```

### Q2: Cache Write Policy 区别

```
Q: "Compare write-through and write-back cache policies."
   "比较 write-through 和 write-back 两种写策略。"

得分点 Marking points:
  ① Write-through: 同时写 Cache 和内存 → 无需脏位，但每次写都访存（慢）
  ② Write-back: 只写 Cache，标记脏位，换出时才写回内存 → 需要脏位，速度快
  ③ Write-through 适合不需要高性能的场景，Write-back 是主流
```

### Q3: 三种流水线冒险

```
Q: "Explain the three types of pipeline hazards and their solutions."
   "解释三种流水线冒险及其解决方法。"

得分点 Marking points:
  ① 结构冒险 (Structural): 硬件资源冲突 → 哈佛架构 / 插入 stall
  ② 数据冒险 (Data): 下条指令依赖上条结果 → Forwarding（大部分）/ Stall（Load-use）
  ③ 控制冒险 (Control): 分支/跳转 → 分支预测 / 延迟槽 / Flush
```

### Q4: 编译器优化如何影响时间？

```
Q: "How do compiler optimizations affect execution time?"
   "编译器优化如何影响程序执行时间？"

得分点 Marking points:
  ① 用 Iron Law: Time = Instr × CPI × CycleTime
  ② 常量折叠/死代码消除 → 减少指令数
  ③ 强度削弱/指令调度 → 降低 CPI
  ④ 循环展开 → 指令数↑但 CPI↓，总时间可能减少（权衡 trade-off）
  ⑤ 删除注释 → ❌ NOT an optimisation（词法分析阶段已移除）
```

### Q5: 硬件中断的处理流程

```
Q: "Give an example of a hardware interrupt and explain how the processor handles it."
   "举例说明硬件中断的来源和处理过程。"

得分点 Marking points:
  ① 例子：键盘按键 / 网卡数据到达 / 定时器
  ② 中断异步发生，取指阶段检查中断信号
  ③ 保存 PC + 状态寄存器 → 查 IVT → 跳 ISR
  ④ ISR 处理 → 发 EO1 → 恢复现场 → IRET
```

### Q6: 图着色寄存器分配

```
Q: "Explain how graph colouring is used for register allocation."
   "解释图着色法如何用于寄存器分配。"

得分点 Marking points:
  ① 生命周期分析 → 构建干涉图（节点=变量，边=生命周期重叠）
  ② 用 N 种颜色着色（N=可用寄存器数），相邻节点不同色
  ③ 着色失败 → Spill（变量存内存）
  ④ 边界规则：A最后用在line N，B定义在line N → 不重叠，可共用

Example / 示例：
  a=1; b=a+2; c=a+b;  干涉图 a-b-c
  着色：a→R0, b→R1, c→R0（a和c不重叠，复用R0）
```

### 高频陷阱 High-Frequency Traps

| # | 陷阱陈述 Trap Statement | 答案 | 解释 Explanation |
|:-|:-----------------------|:----:|:----------------|
| 1 | "Removing comments makes the program run faster" | **False** | 注释在词法分析阶段被移除，不进入 AST，不影响生成的机器码或执行时间 |
| 2 | "Compiler optimisations always reduce instruction count" | **False** | 循环展开增加指令数，但降低 CPI，总执行时间可能减少 |
| 3 | "A TLB miss is the same as a page fault" | **False** | TLB Miss 只是缓存未命中，仍可查页表；Page Fault = Valid=0，需要磁盘加载 |
| 4 | "Write-through cache is faster than write-back" | **False** | Write-through 每次写都访存，比 Write-back 慢。Write-back 只写 Cache，换出才写回 |
| 5 | "Virtual memory requires each process to have its own page table" | **True** | 每个进程有独立虚拟地址空间，OS 为每个进程维护一个页表实现隔离 |
| 6 | "A direct-mapped cache has better hit rate than a fully-associative cache" | **False** | 直接映射每个块只能放一个位置，冲突 miss 更多；全相联可放任何位置，命中率更高（但更慢）|
| 7 | "Increasing cache size always improves performance" | **False** | 增大 Cache 减少 Capacity Miss，但增大 Hit Time，可能得不偿失 |
| 8 | "ARM is a CISC architecture" | **False** | ARM 是 RISC（固定指令长度、Load/Store 架构）；x86 是 CISC |
| 9 | "All CPU instructions take the same number of cycles" | **False** | 不同指令 CPI 不同（如 Load 4 cycles, Arithmetic 1 cycle）|
| 10 | "The operating system runs in user mode" | **False** | OS kernel 运行在内核态（Kernel Mode），有全部权限；用户程序在用户态 |
```

## 12. 📊 Iron Law Performance Calculation / 性能计算

```
Time = Instructions × CPI × ClockCycleTime
CPI = Σ(Cycles_i × Count_i) / Σ(Count_i)

Example / 示例：
  Instr type    Cycles    Count
  Load          4         20M
  Store         4         15M
  Branch        8          5M
  Arithmetic    1         60M

  Total Instr = 100M
  CPI = (4×20 + 4×15 + 8×5 + 1×60)/100 = 2.4
  Time = 100M × 2.4 × (1/2GHz) = 120ms

Compiler optimisation for time / 编译器对时间的优化：
  - Reduce instructions / 减少指令数: constant folding, dead code elim
  - Reduce CPI / 降低CPI: instruction scheduling
  - Trade-off / 权衡: sometimes more instructions but faster (loop unrolling)
```

```

  ADD #0xC    ; lower 4 bits / 低 4 位
              ; actual operand = 0xFC (252)
