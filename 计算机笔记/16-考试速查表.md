## 1. 🔢 Hex 8 指令集（必须背熟）

| Opcode | 指令 | 操作 | 用法 |
|:------:|:-----|:-----|:------|
| 0000 | HLT | 停机 | `HLT` |
| 0001 | LDA addr | R0 = M[addr] | `LDA count` |
| 0010 | STA addr | M[addr] = R0 | `STA count` |
| 0011 | ADD addr | R0 += M[addr] | `ADD count` |
| 0100 | SUB addr | R0 -= M[addr] | `SUB count` |
| 0101 | JMP addr | PC = addr | `JMP loop` |
| 0110 | JGE addr | if R0 ≥ 0: PC=addr | `JGE done` |
| 0111 | JNZ addr | if R0≠0: PC=addr | `JNZ loop` |
| 1000 | INP port | R0 = I[port] | `INP 0` |
| 1001 | OUT port | O[port] = R0 | `OUT 0` |
| 1010 | LDI imm | R0 = imm | `LDI #5` |
| 1011 | ADI imm | R0 += imm | `ADI #-1` |
| 1100 | INC | R0++ | `INC` |
| 1101 | DEC | R0-- | `DEC` |
| 1110 | SHL | R0 <<= 1 | `SHL` |
| 1111 | SHR | R0 >>= 1 | `SHR` |

> ⚡ **operand 只有 4 位** → 直接寻址只能访问 0-15

## 3. ⚡ 流水线与 Hazards（必考画图）

### 5 级流水线
```
F(取指) → D(译码) → E(执行) → M(访存) → W(写回)
```

### 三种 Hazard

| Hazard | 原因 | 解法 |
|:-------|:-----|:-----|
| **结构** | 硬件资源冲突 | 哈佛架构 / 插入 stall |
| **数据** | 下条用上条结果 | **Forwarding**（大部分情况）/ Stall（Load-use）|
| **控制** | 分支/跳转 | 分支预测 / 延迟槽 / Flush |

### Load-use 数据冒险（转发也救不了）
```
LW R1, 0(R2)   ; MEM 阶段才有 R1
ADD R3, R1, R4 ; 下一周期 EX 就需要 → 必须 stall 1 个周期！
```

### 分支预测
```
循环 10 次，"猜跳转"：猜对 9 次，猜错 1 次（最后一次不跳）
猜错代价：flush 流水线已取的指令
```

## 4. 💾 Cache 计算（必考）

### 地址分解
```
地址 = [Tag][Index][Offset]
Offset = log₂(行大小)
Index = log₂(Cache大小 / 行大小 / 相联度)
        （直接映射：行数；N路组相联：组数）
Tag = 地址位宽 - Index位数 - Offset位数
```

### 示例：64KB 直接映射 Cache，64B 行，32 位地址
```
Offset = 6 位（64=2⁶）
行数 = 64KB/64B = 1024 → Index = 10 位
Tag = 32 - 10 - 6 = 16 位
```

### 三种映射
| 方式 | 一个块能放的位置 | 查找 |
|:-----|:---------------|:-----|
| 直接映射 | 1 个（Index 唯一）| 最快 |
| N 路组相联 | N 个 | 较快 |
| 全相联 | 全部 | 最慢 |

### 写策略
| 策略 | 同时写内存？| 脏位？| 速度 |
|:-----|:----------|:------|:-----|
| Write-through | ✅ 同时写 | 无 | 慢 |
| Write-back | ❌ 换出才写 | ✅ 需要 | 快 |

### 性能公式
```
平均访问时间 = Hit Time + Miss Rate × Miss Penalty
```

### 3C Miss
- **Compulsory**：第一次访问
- **Capacity**：Cache 不够大
- **Conflict**：多个地址争同一位置

## 5. 📄 虚拟内存（必考地址转换）

### 虚拟地址 → 物理地址
```
虚拟地址 = [VPN][Offset]
查页表：VPN → PFN
物理地址 = PFN × 页大小 + Offset

示例：
  4KB 页，偏移量 = 12 位
  VPN = VA >> 12
  Offset = VA & 0xFFF
  物理地址 = PFN × 4096 + Offset
```

### TLB 流程
```
VA → TLB查 → Hit? → 物理地址 → Cache → 数据
              ↓ Miss
           查页表 → 更新TLB
              ↓ Valid=0
           Page Fault → 磁盘加载 → 更新页表 → 重新执行
```

### 用户态 vs 内核态
| 模式 | 权限 | 切换方式 |
|:-----|:-----|:---------|
| 用户态 | 受限 | 不能主动进内核 |
| 内核态 | 全部 | 中断/异常/系统调用(trap) |

## 6. 🎨 图着色寄存器分配（必考）

```
步骤：
1. 生命周期分析 → 2. 画干涉图 → 3. 着色 → 4. 分配寄存器

干涉图规则：
  - 节点 = 变量
  - 边 = 两个变量生命周期重叠
  
着色规则：
  - 相邻节点不同色
  - 颜色数 = 可用寄存器数
  - 着色失败 → Spill（放内存）
```

### 边界重叠判定
```
变量 A 最后使用在 line N
变量 B 定义在 line N
→ 不重叠，可共用寄存器！
```

## 11. 📊 Iron Law of Performance / 性能铁律（Past Paper Q5）

```
Time = Instructions × CPI × ClockCycleTime
                ↑           ↑
         total instrs    avg cycles per instr

CPI = Σ(Cycles_i × Count_i) / Σ(Count_i)

Example / 示例：
  Instr type / 类型    Cycles     Count / 次数
  Load                 4          20M
  Store                4          15M
  Branch               8          5M
  Arithmetic           1          60M

  Total Instr = 20+15+5+60 = 100M
  CPI = (4×20 + 4×15 + 8×5 + 1×60) / 100
      = (80+60+40+60) / 100 = 240/100 = 2.4

  Time = 100M × 2.4 × (1/2GHz) = 100M × 2.4 × 0.5ns = 120ms

How to improve / 如何优化？
  - Reduce instructions / 减少指令数: use better ISA / 用更高效的指令集
  - Reduce CPI / 降低CPI: pipelining / 流水线
  - Reduce clock cycle / 提高主频: better technology / 更好的工艺
  But each has trade-offs / 但各有代价（power wall / 功耗墙）
```

## 12. 🔷 PFIX Prefix Instruction / 前缀指令（Question Bank 考点）

> PFIX is from the Transputer; Hex 8 can use a similar mechanism to extend operand range.
> PFIX 来自 Transputer 处理器，Hex 8 可以用类似机制扩展 operand 范围。

```
Problem / 问题：Hex 8 only has 4-bit operand → can only access addr 0-15
           Hex 8 只有 4 位 operand → 只能访问地址 0-15

PFIX solution / 解法：Use an extra instruction to extend the operand
                      用一条额外指令扩展 operand

  PFIX #0xF   ; upper 4 bits = 15 / 高 4 位 = 15
  ADD #0xC    ; lower 4 bits = 12 / 低 4 位 = 12
              ; actual operand = 0xFC (252)
```

## 13. 🧱 Tombstone / T-Diagram（Past Paper Q4）

Used to describe compiler bootstrapping / 用于描述编译器引导过程：

```
Example / 示例：Rust compiler written in Rust, compiled to ARMv7-A
                Rust 写的 Rust 编译器，编译到 ARMv7-A

  ┌──────────┐   ┌──────────┐
  │  Rust    │   │  Rust    │
  │  source  │   │ compiler │
  │          │   │ (binary) │
  │ ARMv7-A  │   │  ARMv7-A │
  └──────────┘   └──────────┘

The chicken-and-egg problem / 鸡生蛋问题：
  First Rust compiler must be compiled by something else
  第一个 Rust 编译器需要用别的编译器编译
  e.g., use GCC (C compiler) to compile the first Rust compiler
  比如先用 GCC 编译第一个 Rust 编译器
```

## 14. 💡 True/False Exam Strategy / 答题策略（Q1 = 30 marks）

```
Step 1: Clearly state "True" or "False" (no mark without classification)
        明确写 True 或 False（不写不给分）
Step 2: Explain why in 1-2 sentences / 用 1-2 句话解释原因
   - False: give a counter-example OR explain what's wrong
            给出反例或解释错在哪
   - True: show it holds in ALL relevant cases (think algebraically)
            说明在所有情况下都成立（用代数/公式）
Step 3: Use truth tables, formulas, or examples to support your answer
        可以用真值表、公式、举例来支撑

Marking / 评分规则：
  ✓ Correct classification + valid explanation = full marks / 满分
  ✗ Only True/False, no explanation = 0 marks / 零分
  ✓ Correct extra content = no penalty / 写对了不扣分
  ✗ Self-contradictory extra content = marks deducted / 自相矛盾扣分
```
