## 1. 从代码到执行 From Code to Execution

```
C/Java 源码 Source code
    ↓  编译器 Compiler
汇编代码 Assembly (.s / .asm)
    ↓  汇编器 Assembler
目标文件 Object file (.o / .obj)
    ↓  链接器 Linker
可执行文件 Executable (.exe / ELF)
    ↓  加载器 Loader
内存中的程序 Program in memory → CPU执行 Execution
```

### 各工具的作用 Toolchain Roles

| 工具 Tool | 输入 → 输出 Input → Output | 做的事 What it does |
|:----------|:--------------------------|:-------------------|
| **编译器 Compiler** | 高级语言 High-level → 汇编 Assembly | 语法分析、优化、生成汇编 / Parsing, optimization, code generation |
| **汇编器 Assembler** | 汇编 Assembly → 机器码 Machine code | 把助记符转成二进制，处理伪指令 / Convert mnemonics to binary, handle pseudo-instructions |
| **链接器 Linker** | 多个目标文件 Multiple objects → 可执行 Executable | 合并代码段，解析符号引用 / Merge sections, resolve symbol references |
| **加载器 Loader** | 可执行文件 → 内存 Memory | 分配内存，加载代码和数据 / Allocate memory, load code & data |

## 2. 函数调用的底层实现 Function Call Under the Hood

### 栈帧结构 Stack Frame Layout

```
高地址 High address
┌──────────────────┐
│  调用者栈帧        │
│  Caller's frame  │
├──────────────────┤
│   参数 Arguments   │
│   返回地址         │
│   Return address │
│   旧帧指针         │◄── 帧指针 Frame Pointer (FP/BP)
│   Old frame ptr  │
├──────────────────┤
│   局部变量         │
│   Local vars     │
│   保存的寄存器      │
│   Saved regs     │
├──────────────────┤
│   临时空间         │◄── 栈指针 Stack Pointer (SP)
│   Temporaries    │
└──────────────────┘
低地址 Low address
```

### call / ret 过程 Calling Convention

```assembly
# 调用前 Before call：把参数放到约定的寄存器 / Put args in designated registers
ADDI  R1, R0, 3       # 第一个参数 First arg = 3
JAL   my_function      # 跳转并保存返回地址到 R31（RA）/ Jump and link

# my_function 内部 Inside the function
my_function:
  ADDI  SP, SP, -8     # 栈指针下移，分配空间 / Allocate stack space
  SW    R31, 4(SP)     # 保存返回地址到栈上 / Save return address
  SW    R5,  0(SP)     # 保存寄存器R5 / Save R5

  # ... 函数体 Function body ...

  LW    R5,  0(SP)     # 恢复R5 / Restore R5
  LW    R31, 4(SP)     # 恢复返回地址 / Restore return address
  ADDI  SP, SP, 8      # 回收栈空间 / Deallocate stack space
  JR    R31            # 跳回调用者 / Jump back to caller
```

## 3. 中断机制 Interrupt Mechanism

### 什么是中断 What is an Interrupt？
CPU 暂停当前工作，转去处理突发事件，处理完再回来继续 / CPU pauses current work to handle an urgent event, then resumes

### 中断流程 Interrupt Flow
```
正常程序执行 Normal execution
    │
    ├──← 外部设备发中断信号 Device sends interrupt signal
    │
    ▼
① 保存当前 PC 和状态寄存器 / Save current PC and status register
② 查中断向量表，找到对应处理程序地址 / Look up interrupt vector table
③ 跳到中断处理程序 / Jump to interrupt handler
④ 处理中断 Handle the interrupt（读键盘数据 / Read keyboard data...）
⑤ 恢复 PC 和状态寄存器 / Restore PC and status register
⑥ 回到原来程序继续执行 / Resume original program

    ▼
正常程序执行 Normal execution
```

### 中断 vs 轮询 Interrupt vs Polling

| 方式 Method | 优点 Pros | 缺点 Cons |
|:------------|:----------|:-----------|
| **轮询 Polling** | 实现简单 Simple to implement | CPU 一直空转检查，浪费 CPU cycles wasted |
| **中断 Interrupt** | CPU 可以做别的事，高效 CPU can do other work, efficient | 实现复杂 More complex |

### 内存保护 Memory Protection
- 操作系统和应用程序的内存隔离开 / OS isolates application memory
- 应用程序不能访问操作系统内存 / Apps cannot access OS memory
- 通过 **基址寄存器 + 界限寄存器** 或 **页表** 实现 / Via base & bounds registers or page tables
