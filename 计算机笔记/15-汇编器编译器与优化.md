## 1. 汇编器与汇编过程 Assemblers

> 基础概念见 [[计算机笔记/06-汇编与工具链\|06-汇编与工具链]]

### 汇编器的工作

**汇编器**把**汇编代码 → 机器码**（一对一翻译，和编译器不同）

```
汇编代码（.s / .asm）          机器码（.o / .obj）
MOV R0, #5          ──►  1010 00000101
ADD R1, R0, #3     ──►  0011 00000011
HLT                 ──►  0000 00000000
```

### 两遍扫描 Two-Pass Assembly

汇编器需要**两遍**才能完成翻译：

```
第一遍 (Pass 1)：
  ─ 扫描所有指令，计算每条指令的地址
  ─ 构建符号表 Symbol Table（标签 → 地址）

第二遍 (Pass 2)：
  ─ 用符号表替换标签
  ─ 生成机器码

为什么需要两遍？
  因为前向引用：JMP loop 中的 loop 在后面定义
  第一遍不知道 loop 的地址 → 先记在符号表
  第二遍用符号表填上地址
```

### 两遍扫描示例

```assembly
    地址  指令
    0     JMP start      ; 第一遍：不知道 start 地址
    1                     ; 第二遍：查符号表 → start = 3
    2     start:          ; 第一遍：记下 start = 2
    3     LDI #5
    4     HLT
```

```
第一遍结束后符号表：
  start → 2

第二遍：JMP start → JMP 2
```

### 汇编器 vs 编译器

| 对比 | 汇编器 Assembler | 编译器 Compiler |
|:-----|:----------------|:----------------|
| **输入** | 汇编代码 | 高级语言（C/Rust...）|
| **输出** | 机器码 | 汇编代码 |
| **翻译比例** | 1 条指令 → 1 条机器码 | 1 行代码 → 多条机器码 |
| **复杂性** | 相对简单 | 非常复杂（语法分析/优化/代码生成）|

### Hex 8 汇编器

> Tom Deakin 的 Hex 8 工具：
> - **模拟器**：https://github.com/tomdeakin/COMS10015_hex8_simulator
> - **汇编器**：https://github.com/tomdeakin/COMS10015_hex8_assembler

```
Hex 8 汇编示例：
  .ORG 0        ; 地址从 0 开始
  LDI #10       ; R0 = 10
  STA count     ; count = R0
loop:
  LDA count     ; R0 = count
  ADI #-1       ; R0 = count - 1
  STA count     ; count = R0
  JNZ loop      ; if count ≠ 0, 继续
  HLT

count: .DATA 0  ; 变量 count，初始值 0
```

### 汇编器伪指令 Assembler Directives（Pseudo-ops）

| 伪指令 | 作用 | 示例 |
|:-------|:-----|:------|
| `.ORG addr` | 设置当前地址 | `.ORG 100` |
| `.DATA val` | 定义数据 | `count: .DATA 0` |
| `.EQU name, val` | 定义常量 | `.EQU MAX, 100` |
| `.BYTE val` | 定义字节数据 | `.BYTE 0xFF` |
| `.WORD val` | 定义字数据 | `.WORD 0xABCD` |
| `.END` | 程序结束 | `.END` |

### 三地址码 Three-Address Code (TAC)

编译器常用的中间表示形式：

```
每条指令最多三个地址（两个操作数 + 一个结果）

例：a = b + c * d

TAC 表示：
  t1 = c * d      ; 临时变量 t1 = c * d
  a  = b + t1     ; a = b + t1
```

### 编译器优化 Compiler Optimizations

| 优化 | 说明 | 例子 |
|:-----|:-----|:------|
| **常量折叠 Constant Folding** | 编译期计算常量表达式 | `a = 3 + 5` → `a = 8` |
| **常量传播 Constant Propagation** | 常量替换变量 | `x = 5; y = x + 3` → `y = 8` |
| **死代码消除 Dead Code Elim** | 删除无用代码 | 删掉结果从未使用的代码 |
| **强度削弱 Strength Reduction** | 用廉价操作替代昂贵操作 | `x * 2` → `x << 1` |
| **循环不变式外提 Loop Invariant** | 把不变计算移到循环外 | |
| **函数内联 Inlining** | 函数调用处直接替换为函数体 | |
| **公共子表达式消除 CSE** | 复用已计算过的表达式 | |

## 3. 优化编译器 Optimising Compilers

### -O0, -O1, -O2, -O3 的区别

```
-O0: 不优化，编译最快，适合调试
-O1: 基本优化（减少代码大小 + 基本优化）
-O2: 大部分优化（不包括以空间换时间的）
-O3: 激进优化（包括函数内联、循环展开等）
-Os: 优化代码大小（比 -O2 更小）
```

### 循环优化 Loop Optimizations

```
循环展开 Loop Unrolling（减少循环控制开销）：
  原始：                   展开 2 次：
  for i=0 to 3             for i=0 to 1
    a[i] = 0                 a[i*2] = 0
                              a[i*2+1] = 0

循环分拆 Loop Splitting：
  原始：                   分拆：
  for i=0 to N              for i=0 to mid-1
    if a[i] > 0               proc_pos(a[i])
      proc_pos(a[i])       for i=mid to N
    else                      proc_neg(a[i])
      proc_neg(a[i])

循环交换 Loop Interchange（优化 Cache 局部性）：
  // 按行遍历（空间局部性好）  // 按列遍历（空间局部性差！）
  for i in rows               for j in cols
    for j in cols               for i in rows
      a[i][j] = 0                a[i][j] = 0
```

## 4. 寄存器分配 Register Allocation

### 为什么需要寄存器分配？

寄存器是 CPU 中最快的存储，但数量**非常有限**（如 32 个）。
编译器必须决定：**哪些变量放在寄存器里？哪些 spill 到内存？**

```
变量很多，寄存器很少：
  int a, b, c, d, e, f, ... (20 个变量)
  vs
  R0, R1, ..., R7 (8 个寄存器)

→ 不可能都放寄存器 → 需要分配策略
```

### 图着色法 Graph Colouring

寄存器分配的标准算法，基于**图着色**：

```
步骤 1：构建干涉图 Interference Graph
  节点 = 变量 / 临时值
  边 = 两个变量不能共用同一个寄存器（因为它们的生命周期重叠）

步骤 2：图着色
  用 N 种颜色（N = 可用寄存器数）给图上色
  相邻节点不能同色
  如果成功 → 每种颜色 = 一个寄存器
  如果不成功 → 需要 spill（把一些变量放到内存）

步骤 3：Spill
  选择着色失败的变量 → 放到内存中
  每次使用该变量时 → 加载到寄存器（load），用完存回（store）
  然后重新尝试着色

例：
  a ←┐
     ├── 重叠 → a 和 b 不能同寄存器
  b ←┘
     ┌── 重叠 → b 和 c 不能同寄存器
  c ←┘
  
  干涉图：a — b — c
  2 种颜色：a = R0, b = R1, c = R0（a 和 c 不重叠，可复用）
```

### 图着色示例

```
代码：
  a = 1;          ; 定义 a
  b = a + 2;      ; 使用 a，定义 b
  c = a + b;      ; 使用 a, b，定义 c
  d = c + 1;      ; 使用 c，定义 d

生命周期 Liveness：
  a: live from line 1 to line 3
  b: live from line 2 to line 3
  c: live from line 3 to line 4
  d: live from line 4 onward

干涉图：
  a — b（重叠）
  a — c（重叠？a 到 line 3，c 从 line 3 开始，边界重叠 → 干涉）
  b — c（重叠）
  c — d（重叠）
  a — d（不重叠：a 在 line 3 结束，d 从 line 4 开始）
  b — d（不重叠）

着色（2 个寄存器）：
  a → R0
  b → R1
  c → R0（c 和 a 可共用：生命期不重叠）
  d → R1（d 和 b 可共用）

生成的代码：
  R0 = 1           ; a
  R1 = R0 + 2      ; b
  R0 = R0 + R1     ; c
  R1 = R0 + 1      ; d
  只用了 2 个寄存器！
```

### 寄存器分配的挑战

```
难点：
  1. 图着色是 NP-hard 问题（编译器用启发式算法）
  2. 函数调用时需要保存/恢复寄存器（caller-save vs callee-save）
  3. 有些寄存器有特殊用途（SP、FP、PC...）

Caller-save vs Callee-save：
  Caller-save：调用者负责保存（调用前 push，调用后 pop）
  Callee-save：被调用者负责保存（函数开头 push，结尾 pop）
```

### 📝 经典考题：图着色寄存器分配

**题型：给代码进行寄存器分配（图着色法）**

```
题目：
可用寄存器：R0, R1, R2（3 个）

代码：
  a = 1;
  b = a + 2;
  c = b + 3;
  d = c + a;
  e = d + 1;

Step 1：生命周期分析
  a: live 从定义到最后一次使用（line 1 → line 4）
  b: live from line 2 to line 3
  c: live from line 3 to line 4
  d: live from line 4 to line 5
  e: live from line 5 往后

Step 2：画干涉图
  a — b（重叠，线 2-3 同时活跃）
  a — c（重叠）
  a — d（重叠）
  b — c（重叠）
  c — d（重叠）
  d — e（重叠）
  其他不干涉

Step 3：着色（3 色表示 3 个寄存器）
  给 a 上色：R0
  b 不能 R0 → R1
  c 不能 R1（和 b 干涉）→ R0 可以吗？c 和 a 重叠？...
  
  让我们仔细看生命周期：
  a: line 1 到 line 4（最后使用在 d = c + a）
  b: line 2 到 line 3
  c: line 3 到 line 4
  d: line 4 到 line 5
  e: line 5 往后

  干涉图：
  a - b: a 到 line 4, b 到 line 3 → 重叠 ✓
  a - c: a 到 line 4, c 从 line 3 → 重叠 ✓  
  a - d: a 到 line 4, d 从 line 4 → 边界重叠 → 干涉 ✓
  b - c: b 到 line 3, c 从 line 3 → 边界不干涉 → 可共用
  c - d: c 到 line 4, d 从 line 4 → 边界不干涉 → 可共用
  d - e: d 到 line 5, e 从 line 5 → 边界不干涉 → 可共用

  简化着色：
  a → R0
  b → R1
  c → R1（和 b 不重叠，可共用！）
  d → R1（和 c 边界不重叠）
  e → R1（和 d 边界不重叠）

  只用 2 个寄存器！✓
```

### 📝 自测：编译器优化

```
题目 1：常量折叠 + 常量传播
  原始：x = 3 + 5; y = x * 2
  优化后：x = 8; y = 16

题目 2：强度削弱
  a = b * 2    →    a = b << 1
  c = d / 4    →    c = d >> 2

题目 3：循环不变式外提
  for (i=0; i<N; i++) {
      x = y + z;     // y+z 每次循环都一样！
      a[i] = x + i;
  }
  优化：t = y + z;        // 提到循环外面
        for (i=0; i<N; i++)
            a[i] = t + i;
```

### ⚠️ 易错点
- **干涉图的边界重叠算不算干涉？** — 一般来说，如果一个变量在 line N 结束（最后一次使用），另一个在 line N 开始（定义），则**不干涉**（可共用寄存器）
- **图着色是 NP-hard** — 考试用的是简化版，按度数从大到小着色即可
- **Spill** 不是失败，是正常的寄存器分配策略的一部分 — 变量太多时就 spill 到栈上
- **caller-save vs callee-save**：调用者保存的寄存器在 call 前 push，callee-save 的寄存器在函数开头 push
