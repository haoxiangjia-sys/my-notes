## Hardware Support for OS & Virtual Memory

## 1. 操作系统的硬件支持

### 为什么 OS 需要硬件支持？

操作系统管理硬件资源，需要 CPU 提供**硬件级别的保护机制**，防止应用程序破坏系统。

### 核心硬件机制

| 机制 | 作用 |
|:-----|:------|
| **双模式操作**（用户态/内核态）| 区分 OS 和应用程序 |
| **特权指令** | 只有内核能执行（如 I/O 指令、修改页表）|
| **内存保护** | 防止应用访问其他进程的内存 |
| **定时器 Timer** | 防止应用垄断 CPU（时间片轮转）|
| **中断/异常** | 应用请求 OS 服务的入口 |

### 双模式 Dual Mode

```
                  ┌──────────────────┐
                  │  应用程序 Apps   │
                  │  (User Mode)     │
                  └────────┬─────────┘
                           │ 系统调用 (trap)
                           ▼
                  ┌──────────────────┐
                  │  操作系统内核    │
                  │  (Kernel Mode)   │
                  └──────────────────┘
                           │
                           ▼
                  ┌──────────────────┐
                  │   硬件 Hardware  │
                  └──────────────────┘

模式切换：
  用户态 → 内核态：只能通过中断/异常/系统调用（硬件自动切换）
  内核态 → 用户态：通过特权指令（如 IRET）
```

### 内存保护 Memory Protection

**基址+界限方案 Base & Bounds**：

```
每个进程有一对寄存器：
  ┌──────────────────────────────────────┐
  │  基址寄存器 Base (起始地址)          │
  │  界限寄存器 Bound (可访问的最大长度) │
  └──────────────────────────────────────┘

进程访问地址 addr：
  检查：Base ≤ addr < Base + Bound
  不满足 → 触发异常（段错误 segmentation fault）

例：
  Base = 1000, Bound = 500
  进程可访问地址：1000 ~ 1499
  访问 1500 → 异常！
```

### 定时器 Timer

```
定时器每隔 N 毫秒发送一次中断：
  → CPU 暂停当前进程
  → OS 调度器决定下一个进程
  → 实现时间片轮转调度

目的：防止一个进程死循环霸占 CPU
```

## 2. 虚拟内存 Virtual Memory

### 什么是虚拟内存？

给每个程序一个**独立的、连续的虚拟地址空间**，映射到物理内存：

```
虚拟地址空间（每个进程独立）    物理地址空间（共享）
    ┌──────────┐               ┌──────────┐
    │ 0xFFFF   │               │         │
    │          │               ├──────────┤
    │          │               │ 进程B页  │
    │ 进程A    │               ├──────────┤
    │ 虚拟内存 │──页表→        │ 进程A页  │
    │          │               ├──────────┤
    │          │               │ 空闲     │
    │ 0x0000   │               ├──────────┤
    └──────────┘               │ 进程A页  │
                               ├──────────┤
                               │ 进程B页  │
                               └──────────┘
```

### 为什么需要虚拟内存？

| 问题 | 虚拟内存的解法 |
|:-----|:--------------|
| 物理内存不够大 | 把不常用的数据放到磁盘（交换 Swap）|
| 程序之间互相干扰 | 每个程序有独立地址空间 |
| 内存碎片化 | 连续的虚拟地址 → 不连续的物理地址 |
| 程序大小超过物理内存 | 只加载需要的部分（按需加载 demand paging）|

### 分页 Paging

```
虚拟内存分成固定大小的块：页 Page（通常 4KB）
物理内存也分成同样大小的块：页框 Page Frame

虚拟地址：
┌────────────┬────────────┐
│ 虚拟页号   │ 页内偏移    │
│ VPN        │ Offset     │
└──────┬─────┴────────────┘
       │
       ▼ 查页表 Page Table
       │
┌──────┴─────┬────────────┐
│ 物理页框号 │ 页内偏移    │
│ PFN        │ Offset     │
└────────────┴────────────┘
```

### 页表 Page Table

```
页表 = 虚拟页号 → 物理页框号的映射表

每个进程有自己的页表：
┌────┬──────┬───┐
│VPN │ PFN  │ V │
├────┼──────┼───┤
│ 0  │  10  │ 1 │  ← 有效，映射到 物理页框 10
│ 1  │  -   │ 0 │  ← 无效（不在内存中 → 缺页异常）
│ 2  │  50  │ 1 │
│ 3  │  -   │ 0 │
│ ...│ ...  │.. │
└────┴──────┴───┘

V 位（Valid）= 0 → 该页不在物理内存中（可能在磁盘上）
访问 V=0 的页 → 触发缺页异常 Page Fault → OS 从磁盘加载
```

### 缺页异常 Page Fault

```
程序访问某地址 → 查页表 → V=0 → 缺页异常
    │
    ▼
1. CPU 切换到内核态
2. OS 检查地址是否合法
3. 合法 → 从磁盘读取该页到物理内存
4. 更新页表（V=1, PFN = 刚分配的页框）
5. 返回用户态，重新执行出错的指令
6. 这次页表有映射了 → 正常访问

如果物理内存满了 → 踢出某页（页面置换）
  常见算法：LRU、FIFO、Clock（近似 LRU）
```

### TLB — 快表 Translation Lookaside Buffer

**问题**：每次访存都要查页表 → 页表在内存中 → 多一次内存访问 → 速度减半！

**TLB 解法**：把最近用过的页表项缓存到 CPU 内部的 TLB

```
TLB = 页表的 Cache

访问地址时：
  1. 先在 TLB 中查找（硬件做，极快）
  2. TLB Hit → 直接得到物理地址（1 个周期）
  3. TLB Miss → 查内存中的页表（几十个周期）
             → 把结果加载到 TLB（下次就快了）

TLB Miss → 额外开销（但比 Cache Miss 影响更大）
```

### 虚拟内存与 Cache 的配合

```
CPU 发出虚拟地址 → TLB 查虚实映射 → 物理地址 → Cache 查数据
                                            ↓
                                    物理地址 = 去内存找

流程：
  Virtual Address → [TLB] → Physical Address → [Cache] → Data

TLB Miss → 查页表 → 更新 TLB
Cache Miss → 从内存读数据
Page Fault → 从磁盘读页 → 更新页表/TLB
```

## 3. Hex 8 视角的虚拟内存

> Hex 8 只有 256 字节内存，不需要真正的虚拟内存。但可以用它来**理解地址转换的概念**。

```
Hex 8 的"地址转换"类比：
  程序里的地址（0-15）→ 实际物理地址（0-255）
  
  LDA 5  → 实际访问哪里？取决于"地址映射"如何设置
  
  这相当于一个简化的"分段"机制
```

### 📝 Classic Exam: Address Translation / 经典考题：地址转换

**Given page table + virtual address → compute physical address / 给页表+虚拟地址算物理地址**

```
Question / 题目：
  Page size = 4 KB (12-bit offset) / 页大小 = 4 KB（12 位偏移）
  Virtual address / 虚拟地址 = 0x3C2F
  Page table / 页表：

  VPN   PFN   Valid
  ────  ────  ─────
  0     10    1
  1     7     1
  2     12    1
  3     5     1
  4     --    0  ← not in memory / 不在内存

  Find physical address of 0x3C2F / 求物理地址

Solution / 解法：
  VPN = 0x3C2F >> 12 = 0x3 (VPN 3)
  Offset = 0x3C2F & 0xFFF = 0xC2F
  
  Page table lookup / 查页表：VPN 3 → PFN 5, Valid=1 ✓
  Physical address / 物理地址 = PFN × PageSize + Offset 
                              = 5 × 4096 + 0xC2F
                              = 0x5000 + 0xC2F
                              = 0x5C2F

Answer / 答：Physical address / 物理地址 0x5C2F
```

**Extension with TLB / 扩展题型 + TLB**

```
TLB initially empty / TLB 初始为空：
  After accessing 0x3C2F:
    ① TLB Miss (empty / 空)
    ② Look up page table in memory / 查内存中的页表 → VPN 3 → PFN 5
    ③ Update TLB / 更新 TLB：VPN 3 → PFN 5
    ④ Physical address / 物理地址 = 0x5C2F

Next access to VPN 3 / 下次再访问 VPN 3：
    ① TLB Hit (cached / 已缓存)
    ② Get PFN 5 directly / 直接得到 PFN 5
    ③ No page table access needed / 不用查页表 ✓
```

### ⚠️ Common Mistakes / 易错点
- **Page size determines Offset bits** / 页大小决定 Offset 位数：4KB = 12 bits, 8KB = 13 bits, 1MB = 20 bits
- **Valid=0 ≠ illegal address**: just means the page is swapped to disk, not necessarily invalid / 只代表不在内存，不一定非法
- **TLB Miss ≠ Page Fault**: TLB Miss → just look up page table again; Page Fault → page's Valid=0, need disk load
- **Cache addressing**: typically uses **physical address** (TLB translation first, then cache lookup) / 通常是物理地址
