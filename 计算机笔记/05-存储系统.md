## 1. 存储器层次结构 Memory Hierarchy（金字塔 Pyramid）

```
              寄存器 Registers (1ns, ~1KB)
            ┌──────────────────┐
           │   L1 Cache (2ns)  │
          │   L2 Cache (5ns)    │
         │    L3 Cache (15ns)    │
        │    内存 Main Memory    │
        │   (50-100ns, GB级别)  │
       │      SSD (10-100μs)     │
      │     HDD (5-15ms, TB级)   │
```

**规律 Trend**：越往上越快、越贵、容量越小 / Higher = faster, more expensive, smaller capacity
**关键思想 Key idea**：用低成本实现接近高速度的性能 / Achieve near-CPU speed at near-disk cost — **利用局部性原理 Leverage locality**

## 2. 局部性原理 Locality

### 时间局部性 Temporal Locality
> 刚访问过的数据，很可能很快再次访问 / Recently accessed data is likely to be accessed again soon

例子 Example：循环中的变量 / Variables in loops `sum += arr[i]`

### 空间局部性 Spatial Locality
> 刚访问过的数据附近的数据，很可能很快被访问 / Data near recently accessed data is likely to be accessed soon

例子 Example：遍历数组遍历 Sequential memory access `arr[0]` → `arr[1]` → `arr[2]`

## 3. Cache 原理 Cache Principles

### 基本概念 Basic Concepts
- **Cache Line（缓存行）**：Cache 和数据交换的最小单位，通常 64 字节 / Smallest unit of data transfer, typically 64 bytes
- **Hit（命中）**：需要的数据在 Cache 中 / Data found in cache
- **Miss（缺失）**：需要的数据不在 Cache 中 / Data not in cache, must fetch from memory

### 三种映射方式 Three Mapping Schemes

| 方式 Scheme | 说明 Description | 优缺点 Pros/Cons |
|:-----------|:-----------------|:-----------------|
| **直接映射 Direct Mapped** | 每个内存块只能去Cache的固定位置 / Each memory block maps to exactly one cache location | 简单 Simple 但冲突率高 High conflict misses |
| **全相联 Fully Associative** | 可以放在Cache的任何位置 / Can go anywhere in cache | 灵活 Flexible 但查找慢 Slow lookup |
| **组相联 Set Associative** | 分成若干组，组内全相联，组间直接映射 / Groups of sets, fully associative within set | 折中方案，最常用 Best trade-off |

### 写策略 Write Policies
| 策略 Policy | 说明 Description |
|:-----------|:-----------------|
| **Write-through （直写）** | 同时写Cache和内存 / Write to both cache and memory simultaneously（简单 Simple 但慢 Slow）|
| **Write-back （回写）** | 只写Cache，换出时才写回内存 / Write to cache only, write back when evicted（快 Fast 但复杂 Complex）|

### Miss 的三种类型（3C）
| 类型 Type | 原因 Cause |
|:----------|:-----------|
| **Compulsory（强制）** | 第一次访问，数据还没进Cache / First access to a block |
| **Capacity（容量）** | Cache太小，装不下工作集 / Cache too small for working set |
| **Conflict（冲突）** | 多个块争同一个Cache位置 / Multiple blocks map to same cache line |

## 4. 冯·诺依曼瓶颈 Von Neumann Bottleneck

**问题 Problem**：CPU 速度增长远快于内存速度 / CPU speed grows much faster than memory speed

```
CPU: 我能每秒处理 10亿 条指令！
Memory: 好的...我给你数据大概需要 100ns...
CPU: 那我等着（白等了几百个周期 / Hundreds of idle cycles）
```

### 解决办法 Solutions
1. **Cache**（最重要的解法 Primary solution）
2. 流水线 Pipelining（让等待期间做其他事 / Do other work while waiting）
3. 多核/多线程 Multi-core/threading（隐藏延迟 Hide latency）
4. 预取 Prefetching（提前把数据加载到Cache / Load data to cache in advance）
